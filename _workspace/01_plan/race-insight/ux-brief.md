# UX Brief — 레이스 상세 요약 블록 (race-insight, Phase 1)

> 근거: `race-insight/planning-context.md`·`requirements.md`(REQ-RI-001~007·101~102·NFR, D1~D3 미결 유지).
> 외부 리서치 없음 — 이 앱의 기존 패턴(ConditionSummary·PanoLineChart·RaceRecordRow)과 트랙사이드 맥락에서 도출.
> 새 화면·새 라우트 없음: 변경 대상은 `/race/:motorId` 스크롤 영역 상단(고정 셸 내부)뿐.
> (기록 주체: 오케스트레이터 대필 — ownership hook 차단으로 ux-researcher 반환 본문 저장.)

## 기존 패턴 레퍼런스 (내부)
| 패턴 | 위치 | 가져올 것 | 주의 |
|---|---|---|---|
| ConditionSummary | 모터 상세 | 1줄 요약 + "할 말 있을 때만 발화"(침묵 원칙) + [보는 법] 보조 다이얼로그(열림 상태는 페이지 소유) | 판단 불가 시 판단하지 않음 → REQ-RI-003 방향 미표시와 동일 철학 |
| PanoLineChart | 모터 상세 | aria-hidden 차트 + canonical=목록 텍스트, 회차 등간격 X축, 차트 단독 소비 금지 | M안 채택 시에만 준용(REQ-RI-101) |
| RaceRecordRow | 레이스 상세 | formatVoltage/formatLapTimeSec/formatFanoHz + tabular-nums, 결과 라벨 RACE_RESULT_LABELS('미정' 포함) | 요약 수치 표기는 행 표기와 반드시 동일 관례 — 다르면 대조 시 불신 |

## 사용자 플로우 (진입→시선 경로→판단)
공통 진입: 트랙 옆, 폰 한 손. `/race` 목록에서 모터 탭 → `/race/:motorId` 상세.
- ① "지난번 몇 V에서 완주했지?": 진입 → 시선이 스크롤 영역 최상단 요약 카드의 **완주 전압대(min~max)와 최근 완주 전압(강조 수치)**에 꽂힘 → 그 전압 그대로/근처로 다음 판 결정. 답 = REQ-RI-001. 목록 스크롤·암산 불필요가 성공 기준.
- ② "전압 올리면 이탈했었나?"(최근 흐름): 진입 → 요약 카드 둘째 줄 **최근 결과 스트릭(완주/이탈 기호+텍스트, 최신순)** → 이탈이 이어지면 보수적으로, 완주가 이어지면 유지/소폭 상향 판단. 답 = REQ-RI-002(+M이면 REQ-RI-102 완주 vs 이탈 전압 대역이 판단을 직접 지지).
- ③ "좋아지고 있나?"(추세): 진입 → 요약 카드 셋째 요소 **방향 텍스트**(예: 랩타임 단축 중/파노 유지) → 세팅 방향 유지 여부 판단. 답 = REQ-RI-003. 판단 불가(결측·표본 부족)면 미표시 — 없는 말은 하지 않는다(ConditionSummary 침묵 원칙).

## 정보 우선순위 (시각 계층 원칙 — 확정 디자인 아님)
1. **완주 전압대 + 최근 완주 전압**: 카드의 주값. RaceRecordRow 우측 주값처럼 큰 수치 타이포(numericTypography 계열) — 진입 1초 내 읽히는 유일한 강조.
2. **최근 결과 흐름**: 보조 줄. 색 단독 금지(REQ-NFR-002) — 기호+텍스트 병행.
3. **추세 방향**: 가장 조용한 텍스트. 발화 조건이 있을 때만(없으면 줄 자체 생략).
- 원칙: 강조는 한 곳(최근 완주 전압)만. [+ 기록] 헤더 주 행동과 위계를 다투지 않는다 — 요약은 표시 전용, 새 행동 진입점 아님(REQ-RI-007).

## S안 vs M안 UX 차이 (D1 미결 — split 권고 유지)
- **S(텍스트 요약 카드 1장)**: 플로우 ①② 즉답 + ③은 방향 텍스트로만. 수직 높이 예측 가능(텍스트 3줄 내외) → 375×667에서 요약+목록 첫 행 동시 노출(REQ-NFR-001) 달성이 쉬움. ConditionSummary와 동형이라 학습 비용 0.
- **M(+미니 차트 + 전압 대역 비교)**: ③이 텍스트 단정이 아닌 형태로 보이고, ②의 "올리면 이탈?"에 전압 대역 비교가 직접 답함. 대신 차트 높이(PanoLineChart 기준 200px급)가 목록 첫 행을 뷰포트 밖으로 밀 위험 — REQ-NFR-001과 정면 긴장. 채택 시 높이 축소·접기 등 완화가 필요하나 이는 layout-designer 몫.
- **권고(planning-context 승계)**: split — S로 수직 예산을 먼저 실측 검토 후, "추세 갈증"이 남으면 M을 2차로. M 일괄 채택 여부는 D1(사용자)에 있음.

## 기존 패턴 재사용 지침
- 요약 카드 = ConditionSummary 문법: 본문 1~3줄 + 우측 [보는 법]류 보조 진입(계산 기준·제외 규칙 설명 다이얼로그, 열림 상태는 페이지 소유). 본문에 계산 설명을 싣지 않는다.
- 수치 표기 = RaceRecordRow와 동일 함수(formatVoltage 등)·tabular-nums — 요약↔목록 행 간 눈 대조 시 표기 불일치가 없어야 한다. 수치 자체의 일치는 D2(표본 윈도우, advisor 정합 기본 제안)에 종속.
- M 차트 = PanoLineChart 계약 그대로: aria-hidden, 회차 X축, 0~1점 미렌더(상위가 텍스트 소유), 결측 점 생략 규칙 명시, 키보드 탐색 비활성.

## UX Check (화면 관점 정제)
- 첫눈: 진입 직후 최근 완주 전압이 화면에서 가장 먼저 읽히는 단일 강조인가. 완주 전압대·최근 흐름·추세 방향이 스크롤 없이 한 카드에 있는가.
- 다음 행동: [+ 기록]이 여전히 유일한 주 행동으로 보이는가. 요약이 탭 가능해 보이는 affordance(카드 눌림감·화살표)를 만들지 않았는가. 목록 첫 행이 뷰포트 안에 남는가 — 밀려나면 실패.
- 오해 위험: 1~2건 축약을 추세로 오독 / '미정' 행이 통계에 든 것으로 오해(제외 고지로 예방, D3) / 요약 전압과 입력 시 추천 전압이 달라 보이는 불신(D2 윈도우 정합) / 스트릭 순서가 목록 최신순과 어긋나 보이는 혼동.
- 먼저 정할 방향: 저장 없는 파생 표시 전용, 카드 1~2장 이내, 기존 목록·입력·초기화 흐름 무변경. mode > copy — 문구 다듬기 전에 "표시 전용 카드"라는 모드가 흔들리지 않는지 먼저 본다.

## Phase 2 프로토타입 확인 목록
1. 375×667에서 요약(+M이면 차트) + 목록 첫 행 동시 노출 실측 — S/M 각각(REQ-NFR-001).
2. fixture 전환: 0건→1건→2건→3+건→미정 포함→초기화, 카피 포함 상태 계약 검증(REQ-RI-004~006).
3. 요약↔목록↔입력 추천 수치 삼자 대조 — D2 채택안 기준 모순 없음.
4. A2(최적 세팅=완주 전압 범위+최근 완주 전압) 정의가 실사용 질문 ①에 실제로 답하는지 사용자 확인.
5. 스트릭 표기의 색 미사용 판별(그레이스케일 확인) + 스크린리더로 요약 낭독 순서(우선순위 1→2→3) 확인.
6. 20+건 fixture에서 진입 지연 체감 없음(REQ-NFR-003).
7. D3 두 안(제외 고지 vs 무표기) 화면 비교 후 사용자 선택.
