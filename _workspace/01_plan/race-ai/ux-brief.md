# UX Brief — 레이스 AI 활용 Phase 1 (2026-07-31, 화면 설계만·구현 금지)

> 대상: `/race/:motorId` 레이스 상세 단일 화면. 새 화면·라우트 없음. planning-context(A1 단일 버튼·섹션형 응답)·ai-requirements(REQ-AI-001~005) 전제. D1~D3 미결 유지.
> 레퍼런스는 외부가 아니라 **이 앱의 선례**: RaceEntrySheet [AI 추천](요청 중 라벨·"AI 추천됨" 배지·근거 helperText), RaceInsightCard(침묵 원칙·[보는 법] 다이얼로그), v2.24 고정 셸(스크롤 영역만 흐름).
> (기록 주체: 오케스트레이터 대필 — ownership hook.)

## 사용자 플로우

    상세 진입 → R22 카드 확인 → (궁금하면) [AI 분석] 탭 → 요청 중 → 응답 읽기 → 다음 판 결정([+ 기록])

| 단계 | 보이는 것 | 사용자가 결정하는 것 |
|---|---|---|
| 진입 | R22 카드(즉시·오프라인) + 회차 목록 첫 행 + [+ 기록] | 숫자만으로 충분한가 — 충분하면 AI 없이 끝 |
| R22 확인 | 완주 전압대·스트릭·추세 + **[AI 분석] 진입점**(근거 충분 시) | 인과 질문("왜/뭘 바꿀까")이 남았는가 |
| 요청 중 | 버튼 라벨 "분석 중…" + 취소. **R22 카드·목록은 그대로**(레이아웃 시프트 없음) | 기다릴지 취소할지 |
| 응답 읽기 | 접힌 응답 카드(요약 1줄) → 펼치면 4섹션 + 근거 표기 + AI 표식 | 어느 섹션을 믿고 쓸 것인가 |
| 다음 판 | 응답의 "다음 판 제안"(L1 — 앱이 저장·적용 안 함 명시) | [+ 기록]으로 직접 세팅 입력 — 여전히 사용자 몫 |

## 진입점 배치 — 후보 비교와 권고

| 후보 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **A. R22 카드 하단 행 [AI 분석]** (기존 [보는 법] 좌측, text 버튼) | "결정론의 보완" 관계가 배치로 드러남·응답이 바로 아래 열려 시선 연속·카드 높이 불변(기존 하단 행 재사용) | 카드 인터랙션이 2개로 늘어남(REQ-RI-007 "탭 affordance 금지"는 카드 본체 기준 — 버튼 행은 예외 선례 있음) | **권고** |
| B. 카드 아래 별도 풀폭 버튼 | 발견성 최고 | 수직 예산 1행 상시 소모 — 목록 첫 행 밀림(REQ-NFR 위반 방향)·위계상 [+ 기록]과 경쟁 | 반대 |
| C. 헤더 액션 | 수직 예산 0 | [+ 기록](라임 contained 주 행동) 옆에 두면 위계 붕괴 또는 발견 불가·응답 표시 위치와 단절 | 반대 |

A 채택 시 위계: [+ 기록](헤더·contained) ≫ [AI 분석]·[보는 법](카드 내 text·small). 주 행동 불변.

## 응답 표현 — 섹션형 4역할 vs 수직 예산

- **권고: R22 카드 바로 아래 인라인 응답 카드, 기본 접힘(요약 1줄+펼치기)**. 시트/모달 반대 — 응답을 R22 수치·회차 목록과 **눈 대조**하며 읽는 게 신뢰 UX의 핵심인데 시트는 화면을 덮어 대조를 끊는다.
- 펼친 상태: ① 진단 ② 이상 신호 ③ 브리핑 ④ 다음 판 제안 — 4섹션 순서 고정(질문 빈도순), 섹션별 소제목+1~2문장. 근거 없는 섹션은 **생략**(침묵 원칙 — "이상 없음"을 문장으로 채우지 않음).
- 수직 예산: 접힘 기본이므로 미호출 시 0행·호출 후 1행(요약)만 상시 점유. 펼침은 스크롤 영역 안이라 목록은 아래로 밀리되 스크롤로 도달 가능 — "첫 행이 initial viewport에서 보존"은 **접힘 상태 기준**으로 판정. 펼침 시 자동 스크롤로 응답 상단 정렬.
- 응답은 비영속(새로고침 소멸, L1) — 세션 내 유지·재호출 정책은 D3.

## 신뢰 UX

- **근거 표기(필수)**: 응답 카드 상단 캡션 "기록 {n}건 기준 · 사유 미입력 {m}건 제외" — R22 excluded 표기와 동일 톤·tabular-nums.
- **AI 표식**: 카드 헤더에 "AI 분석" 라벨 + caption "AI가 생성한 해석입니다 — 다시 분석하면 표현이 달라질 수 있어요"(재호출 변동 고지, temp 0이어도).
- **R22 정합**: 응답 속 수치는 주입값 인용만(REQ-AI-001) — 카드 수치와 같은 formatVoltage 자릿수로 표기해 눈 대조 시 불일치가 없게. 미측정 물리 세팅은 "가능성" 어휘(REQ-AI-002)를 UI가 그대로 노출(단정 어휘로 재가공 금지).
- **"판단 불가" = 정상 응답**(REQ-AI-003): error Alert 금지. 응답 카드 자리에 중립 톤 "분석할 근거가 부족해요 — {사유}. 기록이 쌓이면 다시 시도하세요" — R22 insufficient 카피("기록이 더 쌓이면 흐름이 보여요")와 같은 목소리.
- **L1 명시**: "다음 판 제안" 섹션 끝 caption "제안일 뿐 자동 적용되지 않아요 — [+ 기록]으로 직접 입력".

## 상태별 UX 5종

| 상태 | 표현 | 선례 |
|---|---|---|
| 대기 | [AI 분석] text 버튼(카드 하단 행) — 조용히 존재 | [보는 법] |
| 요청 중·취소 | 버튼 "분석 중…" disabled + [취소] 노출. R22·목록 불변, 스피너는 버튼 내 | [AI 추천] "요청 중…" |
| 성공 | 접힌 응답 카드 등장(요약 1줄)+펼치기. 근거 캡션·AI 표식 | "AI 추천됨" 배지 |
| 실패·오프라인 | 응답 자리 1줄: "분석하지 못했어요 — 결정론 요약은 위 카드에 있어요" + [다시 시도]. **성공 위장·휴리스틱 대체 생성 금지**(REQ-AI-005) | recommend-voltage 폴백 고지 |
| 근거 부족(버튼 비활성) | kind=empty/insufficient·이탈 전부 사유 없음 → 버튼 disabled + 사유 caption("기록 3건부터 분석할 수 있어요") — 호출 전 결정론 게이트 | R22 insufficient 축약 |

- 비로그인: 기존 v2.43 게이트가 본문 자체를 막으므로 별도 상태 불필요(requireSession은 D2·tech-note 소관).

## 기존 패턴 재사용 지침

- 요청 중 라벨·배지·근거 문구: RaceEntrySheet [AI 추천]의 3요소를 어휘까지 재사용("…중…" 라벨 / "AI ○○됨" / 근거는 본문 캡션).
- 도움말: 응답 카드에도 [보는 법] 대신 AI 표식 caption이 역할 수행 — 다이얼로그 추가는 과잉, Phase 2 재검토.
- 침묵 원칙: 근거 없는 섹션 생략·"판단 불가"는 중립 톤 — R22 trend=null과 동일 철학.
- 고정 셸: 응답 카드는 스크롤 영역 내부(헤더·푸터 불변). 새 고정 요소 추가 금지.

## UX Check

- 첫눈: R22 카드가 먼저·즉시, AI는 그 하단의 작은 진입점 하나 — "무료·즉시" 위에 "유료·느림"이 얹힌 구조가 배치로 읽히는가.
- 다음 행동: 응답을 읽은 뒤 시선이 [+ 기록]으로 자연히 가는가 — 제안 섹션 끝 L1 caption이 그 다리.
- 오해 위험: ① 응답 수치≠카드 수치(자릿수·주입 강제로 차단) ② "판단 불가"를 고장으로 오독(중립 톤·Alert 금지) ③ 펼친 응답이 목록을 가려 "기록이 사라졌다" 착각(펼침 시 상단 정렬+접기 상시 노출) ④ 재호출 변동을 버그로 오독(고지 caption).
- 먼저 정할 방향: D1(단일 버튼 — 본 brief는 A1 전제) → 응답 접힘 기본 확정 → D3(세션 유지).

## Phase 2 프로토타입 확인 목록

1. mock fixture로 5상태 전환(대기/요청 중·취소/성공/실패/근거 부족) — 실 LLM 불필요(AC-7 경로 포함).
2. 작은 뷰포트(360×640)에서 접힘 응답 1줄이 목록 첫 행을 initial viewport 밖으로 밀지 않는지.
3. 펼침 시 자동 스크롤·접기 버튼 도달성(한 손 엄지 반경).
4. 응답 수치와 R22 카드 수치의 눈 대조 정합(fixture: 완주만/사유 풍부/사유 없음/표본 부족 4종).
5. "판단 불가" 카피가 실패로 읽히지 않는지(사용자 본인 검토 1회).
6. 요청 중 취소 후 재요청 흐름 — 버튼 상태 잔류 없는지.
