# UX Brief — minicar-motor-lab (미니카 모터 RPM 측정 모바일 웹앱)

> Phase 1 Wave 2 산출물. 입력: `planning-context.md`(UX Check 승계), `requirements.md`(REQ 인용), `decision-log.md`, `analysis-algorithm.md` v2(측정 상태 계약 6종).
> 제품 방향(사용자 확정): 개인 도구 · 단일 사용자 · 모바일 세로 우선 · 로그인 없음 · **디자인 최대한 심플** — RPM·파노는 큰 수치 텍스트로만 표시, 차트·게이지·시각화 금지, 입력도 심플.
> WebSearch 미사용 — 레퍼런스 분석은 일반적으로 알려진 앱 패턴 수준으로 한정.

## 1. 디자인 원칙 (전 화면 공통)

1. **수치가 곧 UI**: 측정 화면의 정보 위계 1순위는 RPM 대형 수치, 2순위는 파노(Hz), 3순위는 상태 라벨. 그 외 장식 요소 없음.
2. **상태를 수치로 위장하지 않는다**: 신뢰 게이트 미달 시 수치 영역에 숫자 대신 상태 텍스트("신호 약함")를 표시한다. 0 RPM·이전 값·쓰레기 값 표시 금지 (REQ-ST-003).
3. **모든 실패 상태는 복구 행동(버튼)과 함께 표시한다**: no-permission → "다시 요청", suspended → "탭하여 다시 시작", 저장 실패 → "다시 저장" (REQ-ST-001/004/005).
4. **한 화면 = 한 가지 일**: 측정 화면은 1-action(녹음 활성화→측정→확정), 기록 입력은 단일 폼, 가이드는 모터 선택→결과 읽기.
5. **색만으로 상태를 구분하지 않는다**: 상태 전환은 텍스트 라벨 + aria-live 동반 (REQ-NFR-003).
6. **layout shift 금지**: 수치 ↔ 상태 텍스트 전환 시 수치 영역 높이를 고정해 화면이 튀지 않게 한다 (측정 중 폰을 모터에 근접시킨 자세에서 시선 이동 최소화).

## 2. 레퍼런스 패턴 분석

시각화 금지·수치 중심이라는 제약에 맞는 도구형 앱 패턴을 참조한다 (일반 지식 기반 — 특정 제품 모사 아님).

| 레퍼런스 유형 | 강점 (가져올 패턴) | 약점 (피할 패턴) | 적용 |
|---|---|---|---|
| 악기 튜너 앱 | 실시간 대형 수치 + "잡힘/안 잡힘" 상태가 첫눈에 구분. 신호 없으면 수치 대신 대기 표시 | 바늘/게이지 시각화 (금지 항목) | 측정 화면: 대형 수치 + 상태 라벨, 신호 미달 시 수치 미표시 |
| 소음 측정계(dB meter) 앱 | 측정 시작/정지 단일 버튼, 측정 중임이 명확 | 실시간 그래프 (금지 항목) | "녹음 활성화" 단일 대형 버튼, measuring 라벨 |
| 스톱워치/랩타임 | "진행 중 → 확정(랩 기록)" 전환과 확정값 잠금이 명확 | — | stable 전환 시 확정값 잠금 + 스타일 전환 |
| 체중/혈압 기록 앱 | 숫자 스테퍼+선택형 입력의 최소 폼, 저장 직후 이력 확인 흐름 | 입력 항목 과다 | 기록 입력: 전압 스테퍼, 주행 결과 세그먼트, 만족 토글 |
| 모바일 뱅킹의 이체 확인 | destructive/불가역 행동 전 명시적 confirm + 영향 범위 고지 | — | 모터 삭제 cascade confirm "기록 n건 함께 삭제" |

## 3. 내비게이션 구조 — 선택과 근거

**선택: 하단 탭 3개 + 작업 화면 스택 push (하이브리드)**

```
[하단 탭 — 상시 노출, 목적지]
  ① 측정 (/)          ← 시작 탭 (앱의 중심)
  ② 이력 (/motors)     ← 모터·기록 관리
  ③ 가이드 (/guide)    ← 전압 추천

[스택 push — 컨텍스트를 갖고 진입하는 작업 화면]
  기록 입력 (/record/new)      ← 측정 stable CTA 또는 이력 탭 "+" 버튼에서 진입
  모터 상세·이력 (/motors/:id) ← 이력 탭에서 모터 탭 시 진입 (REQ-F-009)
  모터 등록/수정               ← 이력 탭 내 bottom sheet (별도 라우트 불요)
```

**근거**
- **기록 입력은 목적지가 아니라 작업이다**: 항상 컨텍스트(확정 측정값 또는 선택된 모터)를 갖고 진입하고, 저장/취소로 끝난다. 탭으로 두면 "빈 폼에 불시 진입"이라는 애매한 상태가 생기고 D2(직접 입력)와 측정 연계 입력의 구분이 흐려진다. 스택 push + 뒤로가기가 폼의 시작·끝을 명확하게 한다.
- **탭 3개는 심플 원칙과 엄지 도달성에 부합**: 4탭 대비 각 탭 타깃이 커지고(44px 이상 확보 용이 — REQ-NFR-003), 각 탭이 "측정한다 / 돌아본다 / 판단한다"라는 사용자의 3가지 업무와 1:1 대응한다.
- **순수 스택(탭 없음)을 배제한 이유**: 측정↔가이드를 오가는 사용(측정 전 가이드로 전압 확인 → 측정 → 기록)이 핵심 여정이라 상시 전환 수단이 필요하다. 매번 뒤로가기로 루트에 돌아가는 스택은 이 왕복을 방해한다.
- 측정 진행 중(measuring) 탭 전환 시 캡처 세션은 종료한다(UX-A2, §13) — 백그라운드 녹음 없음, 상태 꼬임 방지.

## 5. 화면 상세

### S1 측정 화면 — UX의 중심

**상태 6종 시각 계약** (`idle · measuring · stable · weak-signal · no-permission · suspended` — analysis-algorithm v2 §1 canonical). 모든 상태에서 레이아웃 골격(상단 상태 라벨 / 중앙 수치 영역(높이 고정) / 하단 액션 영역)은 동일하고, 각 영역의 내용만 바뀐다.

| status | 상태 라벨 (텍스트) | 중앙 수치 영역 | 하단 액션 | 구분 장치 |
|---|---|---|---|---|
| `idle` | "측정 대기" | 안내 1줄: "모터를 공회전시키고 폰을 가까이 대세요" | **[녹음 활성화]** 대형 primary 버튼 (마이크 아이콘+텍스트) | 수치 없음 — 버튼이 화면 주인공 |
| `measuring` | "측정 중" + 펄스 점 애니메이션 | RPM 대형 수치(정수, 천단위 구분) + 파노 보조 수치(Hz, 소수 1자리) 실시간 갱신. 게이트 미달 프레임에서는 수치 대신 `weak-signal`로 전이 | [측정 중지] secondary | 수치는 중간 명도(미확정 톤), 갱신 중임이 라벨로 명시 |
| `stable` | "측정 완료 · 확정" + 잠금 아이콘 | 확정 RPM·파노 잠금 표시 — 고대비 강조색 + 배경 톤 전환(1회 짧은 전환 효과). 이후 갱신 없음 | **[이 측정으로 기록 만들기]** primary + [다시 측정] secondary | measuring과 확실히 다른 색·라벨·잠금 아이콘 3중 구분. 전환 시 aria-live 알림 |
| `weak-signal` | "신호 약함" | **수치 미표시** — 수치 자리에 "—" + "신호가 약합니다. 모터에 더 가까이 대세요" | [측정 중지] (측정 세션은 유지 — 신호 회복 시 measuring 자동 복귀, 시나리오 D-9) | 숫자가 전혀 없음 — "실패"와 "값"의 시각 구분 (REQ-ST-003) |
| `no-permission` | "마이크 권한 필요" | 일시 거부: "마이크 권한이 거부되었습니다" / 영구 거부: "브라우저 설정에서 마이크 권한을 허용해야 합니다" + 설정 경로 안내 접기/펼치기 (**두 경우 다른 문구** — REQ-ST-001) | 일시: **[권한 다시 요청]** / 영구: [설정 방법 보기] | 복구 버튼이 항상 보임 |
| `suspended` | "오디오 일시 중지됨" | "iOS 정책으로 오디오가 중지되었습니다" | **[탭하여 다시 시작]** 대형 버튼 (탭 핸들러 내 `resume()` — REQ-F-001) | 무음을 수치로 위장하지 않음 (REQ-ST-004) |

추가 계약:
- **비보안 컨텍스트** (REQ-ST-002): `isSecureContext === false`면 idle에서 [녹음 활성화] 비활성 + "HTTPS에서만 측정할 수 있습니다" 안내. 권한 오류 문구와 절대 혼용하지 않는다.
- **confidence는 UI에 노출하지 않는다**: 내부 게이트 판정용. 게이지·퍼센트 표시는 시각화 금지 원칙과 충돌하고, weak-signal 이분법이 사용자 판단에 충분하다.
- **stable 후 캡처 자동 정지** (UX-A1, §13): 확정값 잠금과 동시에 마이크 캡처를 종료한다. [다시 측정]이 새 세션을 시작한다.
- 수치 표기: RPM = 정수·천단위 구분(예: `18,540`), 파노 = 소수 1자리 + 단위(예: `309.0 Hz`), RPM이 위·파노가 아래 보조.

텍스트 와이어프레임 (measuring → stable):
```
┌──────────────────────┐      ┌──────────────────────┐
│  ● 측정 중            │      │  🔒 측정 완료 · 확정   │
│                      │      │                      │
│      18,540          │  →   │      18,540          │  ← 강조색+배경 전환
│        RPM           │      │        RPM           │
│      309.0 Hz        │      │      309.0 Hz        │
│                      │      │                      │
│    [ 측정 중지 ]      │      │ [이 측정으로 기록 만들기]│
│                      │      │    [ 다시 측정 ]      │
├──────────────────────┤      ├──────────────────────┤
│  측정 | 이력 | 가이드  │      │  측정 | 이력 | 가이드  │
└──────────────────────┘      └──────────────────────┘
```

### S2 기록 입력

- 진입 2경로: (a) S1 stable → 파노·RPM **자동 채움, 읽기전용 카드**로 표시 (REQ-F-008 — weak-signal·미측정이면 절대 채우지 않음), (b) S3 "+" → 측정값 카드 자리에 "측정값 없음 (직접 입력 기록)" 표시 (**D2 baseline: 허용, 측정값 비움** — REQ-F-004).
- 폼 구성 (위→아래, 5항목 고정):
  1. **모터 선택** (필수): 최근 사용순 라디오 리스트. 모터 0개면 인라인 "모터 먼저 등록" → 등록 시트 열기. 미선택 저장 시도 → 필드 오류 (dangling 금지).
  2. **측정값 카드**: 자동 채움 시 파노·RPM 읽기전용. 수동 수정 불가(측정 신뢰성 보호), 삭제(비우기)만 허용.
  3. **세팅 전압** (필수): `inputmode="decimal"` 숫자 입력 + ±0.1 V 스테퍼. 허용 범위 0.1~9.9 V (A5). 범위 밖·비수치 → 인라인 필드 오류, 저장 거부.
  4. **주행 결과** (필수, 선택형 — A4): 세그먼트 3택 `완주 · 코스아웃 · 미주행(측정만)` (baseline 제안, §13 D4).
  5. **만족 체크**: 단일 토글 "이 세팅에 만족" (가이드 집계의 원천 — 결과와 독립).
- [저장] 버튼: 탭 즉시 비활성 + "저장 중…" (중복 탭 방지 — 시나리오 H-4). 실패(quota 등) 시 **입력값 유지 + 오류 배너 + [다시 저장]** (REQ-ST-005). 성공 시 스택 pop → 진입 원점 복귀 + 짧은 토스트 "저장됨".

### S3 이력 (모터 목록) / S4 모터 상세

- S3: 모터 카드(이름, 상태 메모 1줄, 기록 수, 최근 기록 요약) 목록. 상단 [+ 모터], [+ 기록](S2 직접 입력 진입). 모터 0개 → 빈 상태: "첫 모터를 등록하세요" + [+ 모터] (오류로 위장 금지 — E-1).
- S4: 해당 모터 기록만 시간 역순 텍스트 행 — `날짜 · 전압 V · RPM(있으면) · 결과 · 만족★`. 차트 없음 (Won't). 헤더에 [수정] [삭제].
- **삭제 계약** (REQ-ST-007, D3 baseline):
  - 기록 삭제: confirm "이 기록을 삭제할까요?" → 확인 시 삭제, 목록·가이드 집계 즉시 반영.
  - 모터 삭제: confirm "**'{모터명}'과 기록 {n}건이 함께 삭제됩니다.** 되돌릴 수 없습니다." — n은 실제 소속 기록 수, 삭제 버튼은 destructive 스타일, 초기 포커스는 [취소]. 확인 시 cascade 삭제. 취소 시 무변경.
  - confirm 닫힘 후 포커스는 트리거 요소로 복귀 (REQ-NFR-003).

### S5 전압 가이드

- 상단: 모터 선택(라디오 리스트 — S2와 동일 패턴). 모터 0개면 등록 유도 빈 상태.
- **만족 기록 ≥ 3건** (D1 baseline, REQ-F-006): 추천 범위를 대형 수치 텍스트로 — `추천 2.8 ~ 3.0 V`. 바로 아래 근거 블록:
  - "만족 기록 {n}건 기준"
  - **전압 분포는 텍스트로**: `2.8V ×2 · 2.9V ×1 · 3.0V ×3` (시각화 금지 원칙 준수)
  - 근거 기록 목록 (S4와 동일 행 포맷 — 전압·측정값·결과)
- **만족 기록 < 3건** (REQ-ST-006): 추천 미표시. "기록 부족 — 만족 기록 {3−n}건 더 필요합니다 ({n}/3)" + [측정하러 가기] 링크(탭 ① 전환). 0·1·2건 모두 동일 계약.
- **분산 큰 경우** (E-4 표현 확정): 범위는 min~max 그대로 넓게 표시하되(A6), 범위 폭 ≥ 0.5 V면 보조 문구 "기록 간 전압 편차가 큽니다 — 근거 기록을 확인하세요" 추가. 숨기거나 좁혀 보정하지 않는다.
- 기록 추가/삭제 후 재진입 시 항상 최신 기록으로 재계산 (stale 집계 금지).

## 9. UX Check

trigger 해당 (planning-context 승계): 권한(마이크) 흐름 + 측정 실패/부분 실패 상태 + 신규 측정 UI. copy 이전에 mode·hierarchy·layout shift·affordance·state clarity를 검토했다.

- **첫눈**: 상단 상태 라벨 하나로 "지금 측정 가능한가 / 측정 중인가 / 실패인가"가 판별된다. 표시된 수치는 신뢰 게이트를 통과한 값뿐 — weak-signal에서는 숫자가 화면에 존재하지 않으므로 "유효한 값인가"라는 질문 자체가 생기지 않는다 (state clarity를 hierarchy로 해결).
- **다음 행동**: 모든 상태의 하단 액션 영역에 primary 버튼이 정확히 1개 — idle=[녹음 활성화], stable=[기록 만들기], no-permission=[다시 요청], suspended=[다시 시작], 가이드 부족=[측정하러 가기]. 사용자가 다음 행동을 찾는 상태가 없다.
- **오해 위험**:
  - measuring의 실시간 수치를 확정값으로 오인 → stable과의 3중 구분(라벨·색·잠금) + 확정 시에만 [기록 만들기] 노출로 차단.
  - 배음으로 RPM 정수배 튐 → v2 파이프라인이 구조적으로 차단(탐색 대역 170~620 Hz 제한 + 고조파 점수) — UI 별도 경고 불요, planning-context의 "대역 밖 경고" 요구는 알고리즘 계층에서 해소됨.
  - 일시/영구 권한 거부 혼동 → 문구·버튼 분리 (REQ-ST-001).
  - weak-signal ↔ measuring 전환 시 화면 튐 → 수치 영역 높이 고정.
  - 측정값 수동 수정 허용 시 기록 신뢰 훼손 → 읽기전용 카드, 비우기만 허용.
- **먼저 정한 방향**: 대형 수치 1-action 측정 화면 / 선택형·스테퍼 입력 / 하단 탭 3 + 작업 스택 / confidence 비노출 / 온보딩 화면 없이 idle이 온보딩.
- **Phase 2 확인** (→ §14): 실기기 권한·suspended·실신호 3종, stable 전환 체감, 수치 갱신 빈도 체감, 주행 결과 선택지 적합성(D4).

## 11. 접근성 (REQ-NFR-003 구체화)

- 측정 status 전이는 aria-live="polite" 영역에서 텍스트로 알림 ("측정 완료, 18,540 RPM" / "신호 약함").
- 상태 구분은 항상 텍스트 라벨 동반 — 색·애니메이션 단독 금지.
- 모든 버튼·폼·confirm은 keyboard 도달·조작 가능. confirm은 focus trap + 닫힘 후 트리거로 복귀.
- 터치 타깃 최소 44×44px — 하단 탭 3개 구성이 이를 여유 있게 충족.
- 로그인 없음 → accessible authentication 해당 없음.

## 12. 반응형 전략 (REQ-NFR-002)

- **모바일 세로 (기준)**: 단일 컬럼, 하단 탭 고정, 측정 수치는 뷰포트 기반 대형 타이포(예: RPM `clamp(56px, 18vw, 96px)`).
- **태블릿/데스크탑 (깨짐 없음 수준, 최적화 범위 외)**: 콘텐츠 max-width ~480px 중앙 정렬 — 모바일 레이아웃을 그대로 유지. 별도 브레이크포인트 설계 없음 (심플 원칙, 단일 사용자 폰 사용이 지배적).
- 가로 회전: 동일 레이아웃 유지, 수치 크기만 축소 — 별도 가로 레이아웃 없음.
